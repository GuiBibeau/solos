# 0024 — Kamino withdrawals target underlying, but execute collateral input

Status: accepted, 2026-09-23. Issue #23 requests an underlying amount; the pinned kLend combined withdrawal instruction accepts **collateral units only** and has no on-chain minimum underlying-output argument. The executor selects collateral units whose predicted underlying output exactly matches the user's positive underlying target at the observed rate, rejects unrepresentable targets, and simulates the signed transaction. Execution then redeems that **fixed collateral input**, not a guaranteed underlying amount. The quote must expose both the target and encoded collateral plus estimated output; the CLI and MCP descriptions must explicitly warn that the rate can change before inclusion and users must check actual credited units and remaining exposure afterward. Confirmation or pre-send simulation is not proof of exact credit.

We retain the underlying target required by the existing Action/CLI/issue contract instead of silently replacing it with a collateral-denominated request. An on-chain bound would require a different protocol instruction or atomic program wrapper; neither exists in the pinned SDK and pretending that a pre-send simulation provides it would be misleading. Until such a bound exists, do not call this an exact-output withdrawal.
