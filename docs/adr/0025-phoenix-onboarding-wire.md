# 0025 — Phoenix onboarding uses an isolated v0 co-signing wire

Status: proposed, 2026-09-23. The pinned Phoenix TypeScript builder example sends a partially signed **v0** transaction to its permissioned `/v1/exchange/send-register-ixs` endpoint; the Rust example uses legacy. solOS initially sent **v1**: local simulation passed, but the one authorized live submission timed out with no confirmed transaction or observed debit. The server's actual rejection reason was not captured, so the version mismatch is a compatibility hypothesis, **not a proven cause**. Use v0 solely for this onboarding API, with validated SDK instructions, fee payer and trader PDA, a 1232-byte wire bound, no address lookup tables or injected compute-budget instructions, and the same no-retry confirmation rules. Keep the v1 boundary for every other operation; do not silently fall back between transaction versions on an ambiguous send. The endpoint reports its HTTP status (not its untrusted response body) when available. Do not declare live onboarding verified until a separate budgeted QA round confirms registration and reconciles wallet rent/fees.

Sources: [pinned TypeScript builder example](https://github.com/Ellipsis-Labs/rise-public/blob/4bd3c505f16f09fdbe9fb2eff035aeaef8b7b12d/ts/examples/10-builder-onboarding-tx.ts), [pinned Rust builder example](https://github.com/Ellipsis-Labs/rise-public/blob/4bd3c505f16f09fdbe9fb2eff035aeaef8b7b12d/rust/sdk/examples/builder_onboarding_tx.rs).
