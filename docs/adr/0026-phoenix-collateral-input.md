# 0026 — Phoenix collateral transfers fix input, estimate output

Status: accepted, 2026-09-23. Maintainer decision for #102 supersedes its original minimum-receipt requirement. The pinned Rise 0.5.26 EmberDeposit instruction encodes only a u64 USDC input and EmberWithdraw only an optional u64 Phoenix-token input; neither carries an on-chain minimum output. The maintainer chose explicit fixed-input transfers with simulated, **non-guaranteed** output estimates and post-confirmation balance reconciliation over delaying all collateral management for an on-chain wrapper. Do not represent preflight, a quote, or confirmation alone as a guaranteed receipt.

Deposit `amount` is wallet USDC base units. Withdrawal `amount` is Phoenix collateral-token base units, **not** a requested USDC output. Both must validate that the official instructions encode exactly that input, use only the configured wallet's `(0,0)` trader and wallet token accounts, and simulate the identical signed transaction before sending. Withdrawals fail closed on any open market exposure, resting or conditional order, pending settlement, incomplete all-market enumeration, stale/unknown risk state or missing withdrawal capability. Never auto-enroll, deposit or withdraw in order tools. An ambiguous submission is not retried; after confirmation read wallet and trader balances and report their actual deltas, including fees and residuals. Live transfers require separate operator approval and a verified exit path.

A future instruction or audited atomic wrapper that enforces minimum receipt would permit a different, stronger contract; it cannot be substituted silently. See [pinned deposit/withdraw codec sources](https://github.com/Ellipsis-Labs/rise-public/tree/4bd3c505f16f09fdbe9fb2eff035aeaef8b7b12d/ts/src/core/ixBuilders).
